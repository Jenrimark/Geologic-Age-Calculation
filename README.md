# Geologic-Age-Calculation · 不同版本地质年代自动对齐模型

将某一年代表版本中的地层界线年龄，自动对齐转换到另一个年代表版本。以各版本对应的地层界线为控制点，**源版本一步直达目标版本**（不经中间版本中转，单个年龄至多插值一次），支持命令行批处理 / 单值即时查询，并提供只读 HTTP/JSON 接口。

## 功能特性

- **一步直达**：源版本直接转换到目标版本，避免经中间版本多次转换造成的误差累积。
- **精确匹配优先**：命中控制点直接取值；未命中取上下相邻控制点做分段线性插值；超出控制点范围不外推。
- **双模式（命令行版）**：批量处理整列年龄并写回新列；或直接输入单个/多个年龄即时打印，不读写任何文件。
- **只读 API 服务**：转换能力封装为 HTTP/JSON 接口，服务绝不写回任何文件，避免覆盖用户原始数据。
- **可追溯**：每条结果标注转换方式（精确匹配 / 插值）与就近匹配的地层单元归属。
- **跨平台**：自动适配 Windows、macOS 及不同用户目录，无需改动代码即可运行。

## 年代表文件定位（跨平台自动查找）

两个脚本都不写死路径，按以下顺序查找年代表文件：

1. 命令行参数 `--xlsx=文件路径`
2. 环境变量 `GEO_XLSX`
3. 脚本同目录下的 `地质年代表（表头）.xlsx` 或 `wjy.xlsx`
4. 用户目录 `~/Desktop/WJY2/`（Windows 与 macOS 的用户目录由系统自动展开）

工作表优先取 `Sheet1`，不存在则自动取第一个工作表。

## 命令行版用法

```bash
Rscript 各版本直接转换_无中介.R [--xlsx=年代表路径]
```

启动后交互流程：

1. 列出可用版本，选择**源版本**（输入列名或编号）与**目标版本**（输入列名或编号）。
2. 选择更新方式：
   - **模式 1 · 处理表格**：输入待处理文件路径与年代数据列名，批量转换后在原文件新增「目标版本 (来自源版本)」列与「_方式」列。
   - **模式 2 · 直接输入年龄**：直接输入一个或多个年龄（空格/逗号/分号/顿号分隔），即时打印结果，不写入文件。

示例：

```bash
Rscript 各版本直接转换_无中介.R --xlsx=./地质年代表（表头）.xlsx
# 选择源版本、目标版本后，模式 2 输入：251.4 250.7
```

## API 服务用法

```bash
Rscript 年代表转换_API服务.R [--port=8787] [--host=127.0.0.1] [--xlsx=年代表路径] [--core=核心脚本路径]
```

参数说明：

- `--port`：监听端口，默认 8787
- `--host`：监听地址，默认 127.0.0.1；绑定 0.0.0.0 时服务无身份验证，勿在不可信网络长期开启
- `--xlsx`：年代表路径，缺省按上文规则自动查找
- `--core`：核心转换脚本路径，缺省取同目录「各版本直接转换_无中介.R」

接口列表：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 接口说明 |
| GET | `/health` | 健康检查（行数、列数、版本数、只读状态） |
| GET | `/versions` | 可用版本列表（序号可直接作为 source/target） |
| GET | `/convert` | 查询参数 source、target、ages |
| POST | `/convert` | JSON body：`{"source":"GTS2004","target":"GTS2020","ages":[251.4,250.7]}` |

GET 示例：

```
GET /convert?source=GTS2004&target=GTS2020&ages=251.4,250.7
```

返回字段：`input`（输入年龄）、`output`（转换后年龄 Ma）、`method`（精确匹配 / 插值）、`stage`（就近匹配的所属地层单元）。服务为只读，结果仅以 JSON 返回，不写入任何文件。

## 转换算法

1. **精确匹配**：输入年龄等于某版本列中的控制点时，直接取目标列对应值。
2. **分段线性插值**：取不大于与不小于输入年龄的相邻控制点，按比例线性插值得到目标年龄。
3. **就近地层归属**：按源版本列就近匹配，标注该年龄所属的阶（Stage），便于核查，不参与年龄计算。
4. 超出控制点范围时不做外推，该年龄标记为转换失败并在结果中说明。
